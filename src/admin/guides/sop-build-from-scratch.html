Standard Operating Procedure · Build from Scratch

Build a new site — content from an old site if there is one, design from anything that inspires it.

For a fresh build (new design, new structure) rather than a like-for-like copy. Two things are decided independently: where the content comes from, and where the design comes from. Works for both club and business sites.

◆
Content and design are separate choices. You can harvest content from an old site and synthesise a brand-new design from three sites the client screenshotted — mix freely. If an old site exists, its earned SEO is still a deliverable — inventory the URLs and 301-map them even on a full redesign.

ELI12 In plain English

  1. Decide where the words come from — an old site (we copy them) or a fresh brief.
  2. Decide where the look comes from — copy one site, mix a few, or from screenshots you like.
  3. Turn that into a simple design recipe — colours, fonts, layout.
  4. Build it properly — fast and findable.
  5. If there was an old site, still save its Google pages so we don't lose visitors.
  6. Result: a brand-new site that keeps any traffic you'd already earned.

CHOOSE The two axes — decided separately

Axis 1

Where the content comes from

An old site exists

Harvest it — don't re-key by hand. Render each page in the in-app browser, get_page_text, scroll + sweep the DOM/network for images across all hosts. Mine every real fact into CONTENT-BRIEF.md, then improve it (seek real experience, credentials, process, pricing factors, proof). Gaps → [CLIENT TO SUPPLY].

No old site

Work from the client brief into CONTENT-BRIEF.md; everything unknown is a clearly-marked placeholder. Never fabricate facts, testimonials or stats.

Axis 2

Where the design comes from

  • Replicate one live site — read its CSS (tokens, type, spacing) and rebuild it clean, one direction.
  • Inspiration from N sites — capture what works across several, then synthesise a NEW system; don't copy any one 1:1, never lift a competitor's brand or assets.
  • From screenshots — read the images: sample the palette, read the type feel, layout and mood; ask for the source URL when a still misses hover/gallery states.
  • From the brand — palette from the logo (colour-count the PNG) + collateral; fonts to match the sector tone.
i
Record the derived design system (4–6 colours, 2–3 type roles, a layout concept) in CONTENT-BRIEF.md before building — the same way whatever the design source was.

5

Staging noindex (S10) → sign-off → deploy → if replacing an old site, cut over with the 301 map (S9) + submit sitemaps (S16).

SHAPE Single-page vs multi-page

Small businesses/trades sometimes want a one-pager. Allowed, deliberately: build the standard sections as anchor blocks on one route, but keep every essential fact in real HTML (not only widgets), use real mailto:/tel: CTAs (S12), and — if it replaces an old multi-URL site — 301 the old server-visible URLs while keeping matching section ids so old fragment links still land (S9). Default to genuine multi-page (S3) where there's enough real content.

STOP Guardrails

!
Never invent content, logos, testimonials, credentials, reviews or stats. Never clone a competitor's brand or site — inspiration is patterns, not assets. Never touch a live domain/DNS without sign-off. If you're replacing a live site, the earned SEO is a first-class deliverable — inventory + 301 it, don't lose it.
