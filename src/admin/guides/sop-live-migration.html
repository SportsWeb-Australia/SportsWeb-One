Standard Operating Procedure · Live-Site Migration

Move a live site to a new build — without losing the traffic it already earns.

For migrating an existing website (with real SEO equity) to a rebuilt Astro site on Vercel, left ready to wire into Business One. The prime directive is a clean cutover that carries every earned ranking across intact.

⚑
Prime directive — zero traffic loss. Capture the SEO baseline first, rebuild at parity-or-better, map every old URL 1-to-1, and never touch DNS without sign-off. A ranking that drops on cutover is the one failure this SOP exists to prevent.

SPINE The migration, phase by phase

0

SEO baseline & forensics before you build anything

You can't preserve what you didn't measure. This produces MIGRATION-BASELINE.md — the authority for the whole cutover.

  • Full URL inventory — union of a crawl of every internal link, the old sitemap.xml + robots.txt, and (if given) the GSC Pages export + GA top landing pages, plus a backlink/site: sweep. An indexed URL missing here becomes a lost-traffic 404 on cutover.
  • Per-URL snapshot — a table: old URL · title · meta · H1 · canonical · word count · existing schema types · traffic/backlink weight · → new route · 301? Sort by weight; the heavy ones are must-preserve.
  • Ranking + query baseline — top queries, positions, monthly clicks. This is the yardstick you re-check in Phase 7.
  • Structured data, NAP & GBP — capture the current schema and the exact Name / Address / Phone as shown on the site and the Google Business Profile.
  • Canonical host & existing redirects — www vs non-www, http→https, trailing-slash policy. Preserve the choice unless a change is intended.
1

Content & image harvest — via Claude-in-Chrome

Builder / Wix / SITE123 / TeamApp sites are JS-rendered — curl returns almost nothing. Use the in-app browser.

  • Content → open each page, get_page_text; mine every hard fact into CONTENT-BRIEF.md (services, story, testimonials with real names, projects, pricing, hours, contact, socials, service areas). Never invent — gaps become [CLIENT TO SUPPLY]. Flag every old-vs-new conflict, never silently pick.
  • Images → they're injected by JS from CDNs. Render + scroll the page through, sweep the DOM for real URLs across all hosts (img.currentSrc||img.src + computed background-image); network-request capture is the fallback. Gallery/lightbox originals often can't be scraped — ask the client, never substitute a stranger's photo.
  • Re-process to the media budget: AVIF/WebP, explicit width/height, hero ≤ 200 KB, real alt.
◆

Embedded code — forms, widgets & third-party embeds

The part most migrations quietly break. Old sites carry live form endpoints, booking/quote widgets, maps, review & social feeds, chat, analytics/pixels. These must be carried across deliberately — a form that silently posts nowhere is a lost lead.

◆ Prompt — inventory & carry embeds
On the old site, find EVERY embedded form, widget, iframe, script and third-party embed.
List each with: what it does, the exact embed/snippet, and (for forms) the real POST
action/endpoint or the provider. Categories to check: contact/quote/booking forms,
maps, review widgets (e.g. Elfsight), social feeds, live chat, analytics + ad pixels,
fonts, cookie/consent banners.

Carry anything that must keep working across VERBATIM — especially form endpoints and
booking links. NEVER invent an endpoint or POST to a made-up URL (Web-Standards S12);
until a real endpoint is supplied use mailto:/tel: or a clearly-labelled preview form.
Flag anything that needs a new account, key, or domain allow-listing before go-live.

2

Rebuild in Astro — Business-One-ready

Match (or apply the chosen new) design; cleaner, faster, accessible, genuinely multi-page.

  • Content in Astro content collections / src/content/ + data files, not baked into components — so Business One can source it later without a rebuild (Standards S18).
  • One shared <SeoHead>: unique title + meta + self-referencing absolute canonical + OG/Twitter + the page's JSON-LD (S4). @astrojs/sitemap; minimal client JS.
  • Connected JSON-LD graph with stable @ids (S5): WebSite + WebPage + the most specific LocalBusiness subtype + Person + Service + BreadcrumbList. No self-serving AggregateRating on the business. AU phone +61….
  • llms.txt + facts in real HTML (S6); real CTAs, never href="#" (S12); WCAG 2.2 AA (S13).
3

SEO parity gate must pass before cutover

For every must-preserve URL from Phase 0 — the checklist that stops rankings dropping.

  • A new route exists whose title, H1 and content depth are equal or better than the old page (thin → thin is a fail).
  • It's in the 1-to-1 301 map (permanent, one hop). Keep the same slug where sensible so no redirect is even needed; 301 only where the URL must change.
  • Internal links point at the new canonical (no chains). Schema, canonical & NAP carried. Zero orphans; key pages reachable without JS in ≤ 3 clicks.
  • Assets are not redirected; every 301 target returns 200, not another redirect.
4

Staging & indexation control

Deploy to a *.vercel.app preview that can never compete with the live domain.

  • noindex,nofollow header + meta, out of sitemap.xml, preview robots.txt Disallow: /, Deployment Protection on (S10).
  • Get sign-off on parity here before any cutover.
5

Cutover runbook you run DNS, Codey preps everything

The go-live sequence. Codey prepares; you execute the DNS change.

  • Same domain (safest, default): point the domain at Vercel; ship the production vercel.json redirects ("permanent": true) + headers; flip noindex → index,follow; real robots.txt + production sitemap.xml. No Change-of-Address needed.
  • New domain: all of the above plus a GSC Change of Address, and keep the old domain live serving its 301s so equity transfers.
  • On go-live: verify in GSC + Bing, submit the sitemap to both, IndexNow ping; confirm a sampled set of old→new returns 301, canonicals return 200, and the branded 404 renders.
✋
Never change DNS or the registrar yourself. Codey hands you the exact records; you make the change. The live domain is never touched without your sign-off.
6

Google Maps & local presence

Local ranking rides on consistency between the site, the schema and the Google Business Profile.

  • Google Business Profile: confirm it's claimed; make the NAP identical to the site + schema; update the GBP website link to the new URL; align categories, hours and service area.
  • On-site: LocalBusiness subtype + areaServed + AU phone in schema; an embedded Google Map + directions on Contact; address privacy for home/service-area businesses.
  • Only build a genuine location page where real local evidence exists — no thin suburb pages (S7).
7

Post-cutover watch — the proof equity transferred

For 2–4 weeks after go-live, watch and fix regressions against the Phase 0 baseline.

  • Monitor GSC index coverage + crawl errors, 404s, query/landing positions vs baseline, Core Web Vitals, schema errors, broken links.
  • A dip that doesn't recover → investigate the 301 map / parity, don't wait.
  • Tag which monitoring steps are candidates to automate inside Business One.

CHECK Verification before “done”

  • Every must-preserve URL → a parity-or-better new page, all in the 1-to-1 301 map.P3
  • Sampled old→new returns 301; no chains/loops/soft-404s; canonical targets 200; assets not redirected.S9
  • Every embedded form/widget carried; forms hit a real endpoint (never an invented one).◆
